01

FOUNDATION & CLI

Installation & API setup

Install the official Python CLI and initialize it with the API key from your Shodan account.

python -m pip install shodan
shodan init YOUR_API_KEY

Security: keep the API key private; do not commit it to repositories or expose it in screenshots.

Account & host commands
shodan info

Show account/API information.

shodan myip

Display the public IP address seen by the service.

shodan host IP_ADDRESS

Retrieve indexed information for a specific host.

shodan honeyscore IP_ADDRESS

Check Shodan's honeypot probability estimate for a host.

Search & data workflow
  • search: query the Shodan dataset.
  • count: return the number of matching results.
  • stats: request aggregate statistics for a query.
  • download / parse: retrieve and process result data, subject to plan and CLI version.
  • convert: convert supported input data formats.
  • domain: look up indexed domain information.
shodan search --limit 10 'product:nginx'
shodan count 'port:443'
Help & usage
shodan --help
shodan COMMAND --help

Consult command-specific help because options and access can vary between CLI releases and account plans.

Core search syntax

Combine free-text terms with structured filters. Use quotes for exact phrases and separate filters with spaces.

product:nginx port:443
hostname:example.com

Search only assets within an explicitly authorized scope.

04

ALERTS & MONITORING

Alert lifecycle

Network alerts monitor changes or newly observed services within a defined IP range or network scope.

  • create: create an alert for a monitored network.
  • list: list active alerts.
  • info: inspect a specific alert.
  • enable / disable: manage alert notification triggers.
  • triggers: list available notification triggers.
  • remove / clear: remove an alert or clear alerts.

CLI command syntax can change; use shodan alert --help for current options.

CLI alert examples
shodan alert list
shodan alert info ALERT_ID
shodan alert triggers

Check the installed CLI's help output for exact subcommands and required arguments.

Operational monitoring workflow
  • Define the organization's owned IP ranges and approved monitoring scope.
  • Create an alert for the approved network range.
  • Select relevant triggers and notification destinations.
  • Review new observations and validate whether they are expected.
  • Document changes, ownership, timestamps, and remediation status.

FIELD WORKFLOW & REFERENCES

Passive reconnaissance workflow
  • Start with a verified organization, domain, ASN, or IP range in scope.
  • Use broad filters to understand the indexed footprint.
  • Refine by port, product, hostname, geography, and service metadata.
  • Correlate observations with asset inventories and other trusted sources.
  • Record timestamps: Shodan data may be stale or incomplete.
  • Report exposures through the approved security process.
Query building checklist
  • What asset or organization is authorized?
  • Which network, location, service, or technology filter narrows the scope?
  • Does the query rely on a plan-restricted filter?
  • Are results current and attributable to the intended owner?
  • Can the finding be validated without intrusive access?

AUTHORIZED USE ONLY // Shodan is a search engine for internet-connected systems. Search results are not permission to access, test, exploit, or interfere with an asset. Use this reference for passive research and defensive inventory within an explicitly authorized scope. Never attempt authentication, exploitation, data extraction, or interaction with cameras, industrial systems, or other sensitive devices without written authorization.
