CS-08 // ACTIVE DIRECTORY

GPO SECURITY REVIEW

A quick reference for reviewing Group Policy Objects, their links and scope, and resultant policy on Windows endpoints. Use the commands as building blocks for authorized assessments and defensive administration.

GROUP POLICYPOWERSHELLWINDOWSDETECTION
Safe-use note: Run administrative commands only in domains you are authorized to assess. The commands here are for inventory, review, and validation; they do not modify GPOs or deploy payloads. Review output for sensitive hostnames and organizational details before sharing it.
PrerequisitesInventoryLinks & scopeEndpoint validationAudit & detectionHardening

01 // Prerequisites

Use a Windows administration host with the Group Policy module available. RSAT installation and permissions depend on your environment.

Import Group Policy module
Import-Module GroupPolicy

If the module is missing, install the appropriate RSAT Group Policy Management feature using your organization's approved method.

List available GPOs
Get-GPO -All | Select-Object DisplayName, Id, Owner, GpoStatus, ModificationTime | Sort-Object DisplayName

Create an inventory baseline. Review unexpected owners, stale policies, and recent modifications in context; timestamps alone do not prove malicious activity.

02 // Inspect a specific GPO

Replace the example display name with the GPO you are authorized to review.

Show GPO details
Get-GPO -Name 'Workstation Baseline' | Format-List DisplayName, Id, Owner, GpoStatus, CreationTime, ModificationTime, Description

The GUID helps correlate the directory object with its corresponding policy files in SYSVOL. Use a known GPO name from your inventory.

Generate a GPO report
Get-GPOReport -Name 'Workstation Baseline' -ReportType Html -Path .\gpo-report.html

The HTML report documents configured settings. Store it securely: it can expose internal configuration details.

03 // Review links and scope

List GPO links for a domain or OU
Get-GPInheritance -Target 'OU=Workstations,DC=corp,DC=example' | Format-List

Replace the distinguished name with the real target in your lab. Review inherited and directly linked policies, enforcement, and blocked inheritance.

Inspect delegation in GPMC
Get-GPPermission -Name 'Workstation Baseline' -All | Format-Table Trustee, TrusteeType, Permission, Inherited -AutoSize

Review which principals have GPO permissions and whether entries are inherited. Follow up on unusual edit/delegation rights using the GPMC Delegation tab and your approved ACL review process.

04 // Validate resultant policy on an endpoint

Refresh policy on a test endpoint
gpupdate /force

This requests a policy refresh; it does not guarantee that every policy extension has completed or that a given GPO applies.

Review computer policy results
gpresult /scope computer /r

Run with suitable privileges to inspect computer policy. Check applied and denied GPOs and the reasons shown by the tool.

Export a resultant policy report
gpresult /h .\gpresult-report.html

Use a disposable or approved endpoint when validating a change. Compare results with the intended scope and baseline.

05 // Audit and detection checklist

  • Enable and centrally collect appropriate Directory Service Changes auditing on domain controllers.
  • Review relevant directory change events, including 5136 (object modified), 5137 (object created), 5139 (object moved), and 5141 (object deleted), where auditing and event generation apply.
  • Establish a baseline for important GPOs and their SYSVOL files; alert on unexplained ACL or content changes.
  • Correlate the actor, GPO GUID, timestamps, change request, SYSVOL changes, and endpoint policy-processing evidence.
  • Investigate unexpected changes to local groups, scheduled tasks, services, scripts, or security controls that align with a GPO change.
  • Validate audit policy and event forwarding in a test environment before relying on detections.

06 // Hardening checklist

  • Restrict GPO edit and delegation rights to the smallest justified administrator group.
  • Review GenericWrite, WriteDacl, and WriteOwner as distinct rights; do not treat them as interchangeable.
  • Check AD permissions and SYSVOL file permissions without disrupting normal policy access or replication.
  • Remove stale GPOs and unused links only after confirming ownership and business impact.
  • Use change control, peer review, backup, and a tested rollback plan for policy edits.
  • Re-run the permission review after remediation and retain evidence of the corrected state.
Remember: A writable GPO does not automatically mean domain compromise. Its impact depends on the exact rights, GPO links, filtering, inheritance, and the security context of the settings applied.
