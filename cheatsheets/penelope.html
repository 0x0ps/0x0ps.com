PENELOPE SHELL HANDLER

A practical quick reference for Penelope, an interactive shell handler that helps manage authorized lab sessions, listeners, transfers, and port forwarding. Commands may vary by Penelope version; use help in your installed build as the source of truth.

SESSION MANAGEMENTLISTENERSFILE TRANSFERPORT FORWARDING
AUTHORIZED USE ONLY. Use only in systems and networks you own or have explicit permission to test. Treat session logs, transferred files, and collected artefacts as sensitive assessment data. Avoid collecting credentials or running privilege-escalation modules unless specifically in scope.

01 / INSTALL & START

Install from Kali's repositories, then start a listener on a chosen TCP port. Replace example ports and addresses with values from your isolated lab.

INSTALL
sudo apt update && sudo apt install penelope
START LISTENER
penelope -p 5000
BUILT-IN HTTP FILE SERVER
penelope -s share

The listener must be reachable from the lab target: verify routing, host firewall rules, and the interface address before troubleshooting the shell.

02 / MAIN MENU & HELP

SHOW COMMAND REFERENCE
help
LIST MODULES
modules
REVIEW MENU COMMAND HISTORY
history

Module names and availability can change between releases. Review each module before running it and confirm that its actions are permitted by the engagement scope.

03 / SESSION MANAGEMENT

LIST ACTIVE SESSIONS
sessions
SELECT SESSION WITHOUT ATTACHING
use 1
INTERACT WITH A SESSION
interact 1
DETACH FROM INTERACTIVE SHELL
Ctrl-D
TERMINATE A SESSION — DESTRUCTIVE
kill 1

Replace 1 with the session ID shown by sessions. Detaching is not the same as terminating: confirm the intended action before using kill.

04 / FILE TRANSFER

UPLOAD A LOCAL FILE
upload ./report.txt
DOWNLOAD A TARGET FILE
download /path/to/approved-file.txt

Confirm the active session and destination before transferring. Downloaded files are commonly stored in the relevant session directory under Penelope's local data folder; check your version's output for the exact path.

05 / PORT FORWARDING

Port forwarding can make a service bound to a target's loopback interface reachable through an existing authorized session. The syntax below reflects the command style documented in the referenced walkthrough; check help if your version differs.

EXAMPLE: FORWARD LOCAL SERVICE
portfwd 127.0.0.1:8080 -> 127.0.0.1:8080

After creating the forward, test the local endpoint (for example, http://127.0.0.1:8080). Use only a service in scope, and remove the forward when the test is complete.

06 / LISTENERS & CONNECTIONS

LIST ACTIVE LISTENERS
listeners
ADD A LISTENER ON A LAB INTERFACE
listeners add -i 192.0.2.10 -p 8888
CONNECT TO AN APPROVED BIND SHELL
connect 192.0.2.20 4321

192.0.2.0/24 is a documentation-only example network. Replace these addresses only with lab endpoints you control. Listener binding and inbound firewall rules must match your lab design.

08 / OPERATOR CHECKLIST

  • Confirm authorization, target scope, callback address, and port before starting.
  • Use a dedicated lab listener and verify host firewall and routing.
  • Record session IDs and keep notes of commands and timestamps.
  • Minimize collection of secrets and personal data; protect logs and downloads.
  • Close sessions, listeners, forwards, and temporary services when finished.
  • Coordinate cleanup with the system owner and preserve evidence if the engagement requires it.
