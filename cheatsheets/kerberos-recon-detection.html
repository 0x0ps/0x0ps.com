CS-09 // ACTIVE DIRECTORY

KERBEROS RECON & DETECTION

A practical reference for checking Kerberos service exposure, reviewing risky account settings, and investigating authentication anomalies in authorized Active Directory environments.

KERBEROSPOWERSHELLNMAPDETECTION
Authorized use: These examples support service discovery and defensive review. Use only on systems you are permitted to assess. This reference does not include password guessing or credential extraction workflows.

01 // Service discovery

Kerberos commonly uses TCP/UDP port 88. Confirm expected reachability from an approved assessment host.

Nmap TCP service check
nmap -sV -p 88 --reason 10.10.10.10

Replace the sample address with an authorized target. An open port indicates reachability, not a vulnerability by itself.

Find Kerberos DNS service records
nslookup -type=SRV _kerberos._tcp.corp.example

Replace the example DNS domain with your lab domain.

02 // Review pre-authentication settings

From an authorized domain-joined PowerShell session with the Active Directory module, list accounts configured not to require Kerberos pre-authentication.

Find accounts with pre-auth disabled
Get-ADUser -Filter 'DoesNotRequirePreAuth -eq $true' -Properties DoesNotRequirePreAuth,Enabled,PasswordLastSet | Select-Object SamAccountName,Enabled,DoesNotRequirePreAuth,PasswordLastSet

Review each result with the account owner. Prefer enabling pre-authentication unless a documented exception requires otherwise.

Review accounts with service principal names
Get-ADUser -LDAPFilter '(servicePrincipalName=*)' -Properties ServicePrincipalName,Enabled,PasswordLastSet | Select-Object SamAccountName,Enabled,PasswordLastSet,ServicePrincipalName

SPNs are normal in many environments. Review service ownership, privilege, password management, and operational need.

03 // Windows ticket and identity context

List cached Kerberos tickets
klist

The output applies to the current logon session; it is not a domain-wide ticket inventory.

Review current token and group membership
whoami /all

Useful when documenting the security context during a controlled validation.

04 // Detection quick reference

  • 4768: Kerberos TGT requested. Review account, source address, result, and request volume.
  • 4769: Kerberos service ticket requested. Compare service-ticket activity with normal baselines.
  • 4771: Kerberos pre-authentication failed. Correlate repeated failures with source and account patterns.
  • Look for bursts across many accounts, unexpected source systems, disabled or nonexistent identities, and unusual time windows.
  • Correlate with endpoint, VPN, DNS, privileged-group changes, and change-management records.

Event generation depends on audit policy and environment configuration. Verify collection on domain controllers and forward logs centrally.

05 // Hardening checklist

  • Require Kerberos pre-authentication unless a reviewed exception is documented.
  • Use long, unique passwords and managed service accounts where supported.
  • Review SPNs and service-account privileges periodically; remove stale entries only after validating dependencies.
  • Apply sensible lockout controls and monitor authentication failures without creating unnecessary denial-of-service risk.
  • Protect and centralize domain-controller logs; maintain time synchronization and alert on anomalous authentication patterns.
  • Document evidence and avoid treating a single event or account flag as proof of compromise.
