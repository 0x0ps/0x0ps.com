CS-10 // RED TEAM TOOLING

MEDUSA AUTH AUDIT

A practical command reference based on the supplied “A Detailed Guide on Medusa” PDF. Covers target and credential lists, service modules, custom ports, logging, concurrency, combo files, and output verbosity.

MEDUSAFTP / SSHAUTHENTICATION AUDITKALI LINUX
Authorized-use note: Medusa tests authentication against network services and can cause account lockouts or service load. Run these examples only against systems you own or have explicit permission to assess, with an agreed scope and rate limits. The IPs and file names are illustrative placeholders; replace them with approved lab values.

01 // Basic syntax & service module

Medusa uses service modules (for example, FTP or SSH). Confirm the module name and service availability in your authorized test environment before starting an audit.

Check installed version / help
medusa -h
Display usage and available options.
Single known username with a password list (FTP example)
medusa -h 192.168.1.141 -u ignite -P pass.txt -M ftp
-h target host, -u one username, -P password file, -M service module.

02 // Username and password lists

Use only a small, approved test list and coordinate with service owners to avoid lockouts.

Test a username list against one known password
medusa -h 192.168.1.141 -U users.txt -p 'LAB_PASSWORD' -M ftp
-U supplies a username list; -p supplies one password. Replace LAB_PASSWORD with a test credential approved for the assessment.
Audit an approved username/password list pair
medusa -h 192.168.1.141 -U users.txt -P pass.txt -M ftp
The supplied guide uses -U for usernames and -P for passwords. Confirm scope and lockout policy first.
Use a host list with approved test credentials
medusa -H hosts.txt -U users.txt -P pass.txt -M ftp
-H reads target hosts from a file. Keep the list limited to explicitly in-scope assets.

03 // Custom port, concurrency & test boundaries

SSH service on a non-default port
medusa -h 192.168.1.141 -U users.txt -P pass.txt -M ssh -n 2222
-n sets a service port; the PDF example uses 2222 instead of the SSH default 22.
Set concurrent login attempts
medusa -h 192.168.1.141 -U users.txt -P pass.txt -M ftp -t 4
-t controls the number of concurrent login threads in the guide's example. Start low and follow the agreed rate limits.
Limit concurrent host testing
medusa -H hosts.txt -U users.txt -P pass.txt -M ftp -T 2
-T controls the number of hosts tested concurrently, as described in the supplied guide.
Stop after a valid result
medusa -H hosts.txt -U users.txt -P pass.txt -M ftp -f
-f stops testing a host after a valid username/password pair is found.
Stop the overall audit after a valid result
medusa -H hosts.txt -U users.txt -P pass.txt -M ftp -F
-F stops the audit after the first valid pair is found on any host.

04 // Output, logs & diagnostics

Save output to a log file
medusa -h 192.168.1.141 -u ignite -P pass.txt -M ftp -O medusa-audit.log
-O writes output to a file. Treat logs as sensitive because they may contain account information.
Read the saved log
less medusa-audit.log
Review the audit output and retain it according to the engagement's evidence-handling rules.
Suppress the startup banner
medusa -h 192.168.1.141 -U users.txt -P pass.txt -M ftp -b
-b suppresses the startup banner.
Increase normal output verbosity
medusa -h 192.168.1.141 -U users.txt -P pass.txt -M ftp -v 6
-v selects verbosity. The PDF lists levels 0–6; higher values display more operational detail.
Set error/debug detail level
medusa -h 192.168.1.141 -U users.txt -P pass.txt -M ftp -w 6
-w selects error/debug detail. Use higher levels only when needed; detailed logs can be noisy.

05 // Combo input files

The guide describes -C for combo entries. The file format depends on the fields supplied; verify the format for your installed Medusa version before running a test.

Example combo file (lab only)
cat > combos.txt <<'EOF' lab-host:lab-user:LAB_PASSWORD EOF
Use only synthetic or explicitly approved test credentials in combo files.
Run against a defined lab combo file
medusa -M ftp -C combos.txt
The PDF shows -C for combo input. Confirm the exact accepted line format with medusa -h and the module documentation before use.

06 // Assessment checklist

  • Confirm written authorization, target scope, service module, and test window.
  • Agree on account-lockout thresholds, request rates, and maximum concurrency before testing.
  • Use dedicated test accounts and short, approved credential lists wherever possible.
  • Capture the command line, timestamps, target, results, and errors in the engagement notes.
  • Protect logs and delete temporary credential files according to the agreed evidence policy.
  • After the test, notify the service owner and document lockouts, exposed services, and recommended controls.
